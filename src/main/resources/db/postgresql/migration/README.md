# PostgreSQL-Migrationen (Kunden-Installationen)

Kunden laufen auf PostgreSQL, der eigene Server auf MySQL. Beide bekommen
dieselben Nachtupdates (ein Image) - also braucht **jede neue Migration zwei
Dateien mit derselben Nummer**:

| MySQL (eigener Server)                         | PostgreSQL (Kunden)                                       |
| ---------------------------------------------- | --------------------------------------------------------- |
| `db/migration/V407__lieferant_notiz.sql`       | `db/postgresql/migration/V407__lieferant_notiz.sql`       |

`PostgresMigrationslinieTest` laesst den Build scheitern, wenn ein Zwilling fehlt.

Alles bis V406 steckt schon in `db/postgresql/basis/V1__basis_schema.sql`
(Neuinstallation auf leerer Datenbank, siehe `FlywayStartSetupConfig`).

## Die haeufigsten Unterschiede

| MySQL                                   | PostgreSQL                                      |
| --------------------------------------- | ----------------------------------------------- |
| `` `name` ``                            | `"name"` (oder ohne Anfuehrungszeichen)         |
| `BIGINT AUTO_INCREMENT`                 | `BIGINT GENERATED BY DEFAULT AS IDENTITY`       |
| `ENUM('A','B')` (Java-Enum)             | `VARCHAR(n)` + `CHECK (spalte IN ('A','B'))`    |
| `BIT(1)` / `TINYINT(1)`                 | `BOOLEAN`                                       |
| `LONGTEXT` / `LONGBLOB`                 | `TEXT` / `BYTEA`                                |
| `DATETIME(6)`                           | `TIMESTAMP(6)`                                  |
| `ADD COLUMN` (Pruefung per Prozedur)    | `ADD COLUMN IF NOT EXISTS`                      |
| `INSERT IGNORE` / `ON DUPLICATE KEY`    | `ON CONFLICT DO NOTHING` / `ON CONFLICT DO UPDATE` |
| `ENGINE=InnoDB ...`                     | weglassen                                       |

Die App verbindet sich **ohne Superuser-Rechte** (Rolle `erp_user`, Eigentuemerin
von Datenbank und Schema `public`). Migrationen duerfen also Tabellen, Indizes usw.
anlegen und aendern, aber z. B. keine nicht vertrauenswuerdigen Erweiterungen
(`CREATE EXTENSION`) installieren. Der Starttest prueft genauso.

Indexnamen gelten in PostgreSQL im ganzen Schema (MySQL: je Tabelle) - also
eindeutig benennen, z. B. `tabelle__index`.

## Pruefen

Die Spaltentypen muessen zur App passen (`ddl-auto=validate`). Sicherster Weg:
`scripts/basis-schema/postgres_erzeugen.sh <image> --nur-pruefen` mit einem
Image, das die neue Migration enthaelt - oder `deployment/docker-server/starttest.sh`
mit PostgreSQL (`STARTTEST_DB=postgres`).
